## 已作出的实现决定

1. 默认使用 `reset_mode: fixed`，落实用户指定的训练/测试日历；保留 `randomized_aligned` 以复用原 ±7 天及随机小时机制。原代码不改。代价：默认协议不等同于旧脚本中任务/外部时钟互相错位的轨迹。
2. 默认 `weather_augmentation: false`，使用对应 2023 UTC 气象序列；显式启用时保留旧代码有种子的天气扰动。代价：无法将新结果直接视为旧天气随机滚动协议的数值复现。
3. 修正外部数据适配层的时间插值和实际物理输入时钟；保留 IT/HVAC/Battery 公式，以及原 SustainDC 内部先执行物理步、再更新任务占用的顺序。代价：原有资源占用传入物理模型的间隔约定仍存在，已在 README 说明。
4. 任务来源 DC 使用按 episode seed + UTC interval 派生的局部随机流，沿用原人口/本地活动概率。代价：具体来源抽样顺序不同于旧脚本，但消除了策略/Replay 采样对测试工作负载的污染。
5. 保留原 SAC 按槽位匹配下一时刻任务的 Bellman target，未擅自改成新的状态聚合算法。代价：跨时刻槽位不是同一任务身份，此研究方法限制仍存在。
6. memmap 使用与 FastReplayBuffer 完全一致的 dtype；两个轮换 WAL 仅回收本实验内部已失效的临时事务日志，不清理任何已有结果。最近提交的完整检查点可恢复；更旧的网络快照保留用于推理。代价：恢复历史检查点的完整 Buffer 状态不受支持。
7. 总步数严格等于 10,000,000；最后一个 Episode 如未结束，仅保存最终推理模型，完整恢复从最近已提交边界重放。代价：不保存中途环境对象，断电最多重放一个周期及边界延迟。
8. `max_tasks=400` 保持论文值。预检查区分新到达数与最坏持续 Defer 队列上界；运行时真实队列超过 400 必须报错，禁止截断。代价：不能承诺任意已训练策略均不会超过 400；正式训练前必须接受此限制或另行明确修改协议。
9. 使用原始 workload 的只读嵌套目录/ZIP 回退，不在源数据目录解压或生成文件。代价：配置中的字面路径不存在时，manifest 必须记录实际解析路径。
10. 本次采用当前会话实施和一次独立审查，之后复核重要修复。未修改原有核心源码，未自动提交、推送或合并。

## 验证与修复

- 先编写独立契约测试，确认缺失模块导致失败，再实现。
- Windows `fsync` 需要可写句柄：测试复现并修正。
- 中途日志加载了下一时段观察，导致任务分母误计：回归测试复现后仅统计 `arrival_time < current_time`。
- 新增排他 OS 文件锁，防止两个进程同时打开同一 memmap。
- 独立审查发现物理温度/CI 滞后一拍：实际消耗字段回归失败后，适配器在物理步前注入正确 UTC 输入。
- 发布后、提交前中断可能留下孤立检查点：故障注入复现后保留原文件，重放使用 retry 文件名。
- POSIX 检查点重命名和首次 WAL 创建均加入目录 fsync；故障测试确认同步失败前不覆盖已提交行。
- 恢复预检查按已实际分配的磁盘块抵扣已有 Buffer，不重复要求一份新 Buffer。
- 推理快照显式拒绝用作完整恢复；主动本地执行与超期强制回源分开计数。
- 正式模式默认依次训练全部三个种子，同时允许指定尚未开始的有序种子子集，避免中断后重训已完成模型。
- 原 `tests/test_env_setup.py` 触发旧 loader 解压，生成标准路径 `.pkl` 副本；已比较新副本、原嵌套文件及最初 manifest，三者 SHA256 完全一致。副本保留，不做自动清理；新只读 loader 无此写入行为。
